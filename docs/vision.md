# Agent Forge vision

Agent Forge helps developers turn repository tasks into reviewable, verified changes. A developer should be able to run the agent locally, see what it changed and why the checks passed, and use the same workflow through a hosted service.

The first users are the maintainer and invited developers working on real repositories. The project’s first objective is to build and demonstrate professional skill in coding-agent engineering and cloud operations. The hosted pilot gives users a real service to try and gives maintainers evidence about reliability, usability, and operating cost.

A useful release preserves the developer’s work, produces a patch tied to a known base, and reports how the patch was verified. The hosted experience adds asynchronous submission and retrieval. The core remains a small, measurable, domain-agnostic harness. The service adds identity, tenancy, operations, and a user interface around the shared runner.

The [strategy](strategy.md) explains how to pursue this vision. The [roadmap](roadmap.md) tracks delivery outcomes and links to their issues.
