# Agent Forge vision

Agent Forge helps developers turn repository tasks into reviewable, verified changes. A developer can run the agent from the CLI or any ACP-compatible IDE, and the planned roadmap adds Agent Forge Studio (Web and Electron desktop) alongside the hosted service using the same workflow.

The first users are the maintainer and invited developers working on real repositories. The project’s first objective is to build and demonstrate professional skill in coding-agent engineering and cloud operations. The hosted pilot gives users a real service to try and gives maintainers evidence about reliability, usability, and operating cost.

A useful release preserves the developer’s work, produces a patch tied to a known base, and reports how the patch was verified. The hosted experience adds asynchronous submission and retrieval, while standard Agent Client Protocol (ACP) integration connects editors to one shared runtime without custom protocols. The core remains a small, measurable, domain-agnostic harness, and external clients add IDE, desktop, tenancy, and web UI layers around the shared runner.

The [strategy](strategy.md) explains how to pursue this vision. The [roadmap](roadmap.md) tracks delivery outcomes and links to their issues.
